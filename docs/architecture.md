# 架构

SwiftUI 应用启动打包后的 Python 后端，使用标准输入／输出 JSON 行传递命令和状态。界面负责连接提示、预览展示与录像按钮；后端负责网络、缓存和挂载生命周期。

```text
Finder / Insta360 Studio
          │ 只读 NFS v3，回环地址
          ▼
      bridge.py ── camera_io.py ── HTTP Range / OSC ── X5
                                                       ▲
SwiftUI ── JSON lines ── app_backend.py ── live_camera.py ┘
                                         TCP 实时预览
```

相机默认地址为 `192.168.42.1`，HTTP 端口为 80；实时预览使用单独的相机 TCP 协议。应用不会自动修改 Mac 的 Wi-Fi 配置，也不需要用户向应用提供热点密码。

`camera_io.py` 发现目录后查询文件长度。媒体读取使用独立 HTTP 连接，避免相机在声明的响应体之后留下额外数据，污染后续响应。GET 读取对部分瞬时错误有限重试，录像控制等有副作用的命令不自动重复发送。收到的数据必须通过范围和长度校验后才能进入缓存。

缓存按 1 MiB 分块，两个网络工作线程读取并预取。默认内存缓存约 128 MiB、临时磁盘缓存 2 GiB；缓存只存已访问的数据块。应用正常断开时清理缓存，下一次初始化缓存目录时也清理遗留块。异常退出不能保证即时清理。

NFS 服务只监听回环地址，提供只读操作；读取工作线程数受限，避免大文件读取阻塞全部元数据请求。挂载使用 macOS 自带 `mount_nfs`，因此无须 FUSE。系统授权由 macOS 处理，应用不读取管理员密码。

实时预览解析相机数据帧，通过 PyAV 解码 H.264，再把缩小后的 JPEG 发送给界面。当前没有调用官方拼接 SDK，也不实现球面视角选择。帧率与显示尺寸受限以控制 CPU 和进程通信开销。

素材仍打开时卸载可能返回繁忙；此时后端保持运行，允许用户关闭素材后重试。不要在编辑期间强制终止后端或关闭相机。需要修复的问题请通过 GitHub Issue 提交，附去除个人信息后的复现记录。
