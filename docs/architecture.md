# 架构

SwiftUI 应用启动打包后的 Python 后端，使用标准输入／输出 JSON 行传递命令和状态。界面负责连接提示、预览展示与录像按钮；后端负责网络、缓存和挂载生命周期。

```text
Finder / Insta360 Studio
          │ 只读 NFS v3，回环地址
          ▼
      bridge.py ── camera_io.py ── HTTP Range / OSC ── X5
                                                       ▲
SwiftUI ── JSON lines ── app_backend.py ── live_camera.py ┘
                                         TCP 实时预览
```

相机默认地址为 `192.168.42.1`，HTTP 端口为 80；实时预览使用单独的相机 TCP 协议。应用不会自动修改 Mac 的 Wi-Fi 配置，也不需要用户向应用提供热点密码。

`camera_io.py` 发现目录后查询文件长度。媒体读取使用独立 HTTP 连接，避免相机在声明的响应体之后留下额外数据，污染后续响应。GET 读取对部分瞬时错误有限重试，录像控制等有副作用的命令不自动重复发送。收到的数据必须通过范围和长度校验后才能进入缓存。

缓存按 1 MiB 分块，两个网络工作线程读取并预取。默认内存缓存约 128 MiB、临时磁盘缓存 2 GiB；缓存只存已访问的数据块。应用正常断开时清理缓存，下一次初始化缓存目录时也清理遗留块。异常退出不能保证即时清理。

NFS 服务只监听回环地址，提供只读操作；读取工作线程数受限，避免大文件读取阻塞全部元数据请求。挂载使用 macOS 自带 `mount_nfs`，因此无须 FUSE。系统授权由 macOS 处理，应用不读取管理员密码。

实时预览解析相机数据帧，通过 PyAV 解码 H.264，再把缩小后的 JPEG 发送给界面。全景流是左右两个鱼眼，`PanoramaView.swift` 使用 Metal 对视线作球面旋转，再映射到两侧鱼眼并混合接缝；单镜头流是普通矩形。显示帧限制到约 15 fps / 1440 像素，鼠标拖动直接重绘最近的 GPU 纹理。当前没有官方标定、拼接 SDK 或陀螺仪稳定。

模式控制通过 TCP 命令 65 / 66 设置／读取镜头，7 / 8 写入／读取 VIDEO_SUB_MODE (41)。X5 固件 `A3_1.13.21.623_build1` 实测普通视频为 0，云台／动态跟拍为 15；该数值并非 StartCapture 的 mode 枚举。切换前确认空闲，暂停预览，写入后读回确认，再恢复预览。失败时显示实际值，不把部分成功显示为整体成功。录像按钮不再先重设 `captureMode=video`，避免覆盖已选模式。

素材目录读取前建立 TCP 控制会话，每 2 秒发送协议心跳，挂载期间关闭预览也不中断。15 秒没有接收数据时关闭失效连接，主循环按至少 8 秒间隔尝试重连，只同步状态，不自动开启预览、录像或再次切换模式。应用主动断开后停止保活，不更改相机的自动关机设置。

素材仍打开时卸载可能返回繁忙；此时后端保持运行，允许用户关闭素材后重试。不要在编辑期间强制终止后端或关闭相机。需要修复的问题请通过 GitHub Issue 提交，附去除个人信息后的复现记录。


## 0.5.1 录像与控制超时修复

录像改为当前 TCP 会话中的命令 4（StartCapture，Capture_MODE_NORMAL=1）和 5（StopCapture），不再依赖 OSC 的 done 响应。真实 X5 已观察到 OSC 返回 done 但实际状态仍为空闲，且停止请求曾返回开始请求的名称。命令确认后轮询命令 15，只有读回 recording / idle 才显示操作成功；开始、停止指令均不自动重发。丢失响应时只读回状态，避免重复启动录像。

X5 InstaFrame 实际录像状态为 30，旧公开枚举未包含它；旧代码误判为 busy，会禁用停止按钮。现在映射为 recording；未来未知值保持 unknown，保留停止入口。

控制命令 6 秒无应答时主动废弃失效的 TCP 连接，即使预览或心跳数据仍在到达。后续状态读取或保活循环重建控制连接；不操作 Mac Wi-Fi，不更改相机自动关机设置。超时只结束控制会话，原有素材挂载不受此清理直接影响。
